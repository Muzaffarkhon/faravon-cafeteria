# Новости: всплывающие карточки + лента + рассылка в бот

## Контекст

Сейчас в системе нет способа показать сотрудникам единоразовое объявление с картинкой и форматированным текстом, которое:
- всплывает при заходе на витрину, пока не будет отмечено прочитанным;
- дублируется как сообщение в Telegram-боте со ссылкой на полную версию на сайте;
- нацеливается на сегмент сотрудников (как существующие рассылки), а не только «всем».

Ближайшая существующая функциональность:
- `src/app/(admin)/admin/broadcast/` — одноразовая рассылка текста в Telegram (сегментация аудитории, шаблоны с плейсхолдерами `{siteUrl}`/`{botUrl}`, доставка через `Notification`/`NotificationTemplate`). Не хранит контент как отдельную сущность, нет попапа, нет фото, нет read-tracking.
- `TextBlock` — синглтон-текст по ключу (напр. `NOVELTY_NOTICE`), не подходит для списка новостей.
- `RichTextarea` / `FormattedText` (добавлены в этой же сессии для поля `Partner.terms`) — компоненты форматирования текста с хоткеями (Ctrl+B/I/U, Ctrl+Shift+X, Ctrl+Alt+1) и рендер в JSX без `dangerouslySetInnerHTML`. Переиспользуются для новостей без изменений.
- `ImageUploadField` — загрузка/кроп/оптимизация изображения через Vercel Blob (сейчас `purpose: "card" | "banner"`), используется для лого партнёра. Переиспользуется для фото новости с новым `purpose: "news"`.
- `resolveAudience()` (`src/lib/broadcast-audience.ts`) — резолвинг сегмента (отдел/должность/поиск) в список userId. Переиспользуется для таргетинга новости.
- Конвейер доставки в Telegram: `Notification` + `NotificationTemplate` + `deliverTelegramNotifications()` (крон + long-poll бота). Переиспользуется с новым `event: "NEWS"`.

## Требования (подтверждено с пользователем)

1. Админ создаёт новость: заголовок, текст с форматированием (bold/italic/underline/strike/heading), одно фото (опционально), таргетинг аудитории — как в рассылках (сегмент по отделу/должности/поиску, либо «все»).
2. Публикация — отдельное действие от создания (черновик → публикация).
3. Отправка в Telegram-бот — отдельное действие от публикации (кнопка «Отправить в бот» после публикации, как в разделе «Рассылки»). Сообщение в боте содержит краткий текст + ссылку на полную новость на сайте (`{siteUrl}/news/{id}`).
4. Попап на витрине сотрудника (НЕ в админ-панели):
   - показывает ровно одну непрочитанную новость за раз — самую старую непрочитанную для этого пользователя;
   - кнопка «Понятно» — помечает прочитанной навсегда (запись в БД), при следующем заходе покажется следующая по очереди непрочитанная (если есть);
   - кнопка «X» — ничего не пишет в БД, только прячет попап в текущей вкладке браузера (client-side флаг). При новой вкладке/следующем заходе на сайт попап снова появится, пока не нажмут «Понятно».
5. Есть лента новостей на сайте (`/news` — список опубликованных, `/news/[id]` — детальная страница). Именно на `/news/[id]` ведёт ссылка «Подробнее» из попапа и из сообщения бота.
6. Кассиры-партнёры (роль `CONTRACTOR`) новости не видят — ни попап, ни ленту, ни рассылку в бот.
7. Правка уже опубликованной новости НЕ сбрасывает отметки «прочитано» у тех, кто уже видел (чтобы опечатка не спамила всех попапом заново).
8. Есть переводы (tg/uz) заголовка и текста — тот же паттерн `translations Json?` + `TranslationFields`, что у партнёра.

## Модель данных

```prisma
model News {
  id             String    @id @default(cuid())
  title          String
  body           String                      // markdown-подобная разметка (см. FormattedText)
  imageUrl       String?
  status         String    @default("DRAFT") // DRAFT | PUBLISHED
  audience       Json?                       // формат сегмента как у Broadcast; null/{} = все сотрудники
  translations   Json?                       // { tg?: {title?, body?}, uz?: {...} }
  publishedAt    DateTime?
  telegramSentAt DateTime?
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt
  reads          NewsRead[]

  @@index([status, publishedAt])
}

model NewsRead {
  id     String   @id @default(cuid())
  newsId String
  userId String
  readAt DateTime @default(now())

  news News @relation(fields: [newsId], references: [id], onDelete: Cascade)
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([newsId, userId])
  @@index([userId])
}
```

`NewsRead` пишется только по кнопке «Понятно». Нет отдельного «snoozed»-состояния в БД — X обрабатывается полностью на клиенте.

## Поток показа попапа

1. На главной странице кабинета сотрудника (`src/app/(app)/page.tsx` или общий layout `AppShell`) сервер запрашивает: `News` где `status = PUBLISHED`, пользователь входит в `audience` (или `audience` пусто = все), и нет `NewsRead` для (newsId, userId) — сортировка по `publishedAt asc`, берём первую.
2. Если пусто — попап не рендерится.
3. Если есть — клиентский компонент `<NewsPopup news={...} />` проверяет `sessionStorage['news-dismissed:'+news.id]`:
   - если флаг стоит — не показывает (это и есть эффект X в рамках вкладки);
   - иначе — показывает модалку с заголовком/фото/форматированным текстом, кнопками «Понятно» (server action → пишет `NewsRead`, закрывает) и «X» (просто `sessionStorage.setItem(...)`, закрывает, ничего на сервер не шлёт).
4. Ссылка «Подробнее» внутри попапа ведёт на `/news/[id]`.

Ограничение: это НЕ показывается внутри `AdminShell` (админ-панель) — только в `AppShell` (личный кабинет сотрудника).

## Публикация и отправка в бот

- Форма новости (`/admin/news/new`, `/admin/news/[id]`) — аналог формы партнёра: заголовок, `RichTextarea` для текста с подсказкой хоткеев, `ImageUploadField` (purpose `"news"`), выбор аудитории (переиспользуем UI сегмента из Broadcast), `TranslationFields`.
- Кнопка «Сохранить черновик» — `status: DRAFT`.
- Кнопка «Опубликовать» — `status: PUBLISHED`, `publishedAt: now()`. С этого момента видна в попапах и в `/news`.
- После публикации появляется кнопка «Отправить в бот» — резолвит аудиторию через `resolveAudience()`, создаёт `Notification` (`event: "NEWS"`, `channel: "TELEGRAM"`) для зарегистрированных пользователей + прямая отправка гостям (как в `sendBroadcast()`), текст собирается из `title` + обрезанного `body` + ссылки `{siteUrl}/news/{id}`. Ставит `telegramSentAt`.
- RBAC: используется то же право, что уже гейтит раздел «Рассылки» (уточняется в момент реализации, без нового права).

## Лента новостей

- `/news` (в составе `(app)` route group, доступно сотрудникам, не кассирам) — список `PUBLISHED` новостей, сортировка по `publishedAt desc`, карточка = заголовок + превью текста + миниатюра фото.
- `/news/[id]` — полная новость: заголовок, фото, `FormattedText` от `body`, дата публикации. Открытие этой страницы НЕ помечает новость прочитанной автоматически — прочтение фиксируется только через «Понятно» в попапе (чтобы не путать «открыл ссылку из бота» с «подтвердил на сайте»).

## Доступ

- Роль `CONTRACTOR` — не видит `/news`, `/news/[id]`, попап не рендерится, в `resolveAudience()`/таргетинге для новостей эта роль исключается на уровне запроса (не полагаемся только на скрытие UI).

## Вне рамок (не делаем сейчас)

- Push-уведомления вне Telegram.
- Многократные фото в одной новости (только одно, как логотип партнёра).
- Автоматический сброс «прочитано» при редактировании.
- Закрепление/приоритет новостей, сроки действия (expires).
