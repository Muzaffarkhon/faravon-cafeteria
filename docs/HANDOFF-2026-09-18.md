## 1. Перенос на новый аккаунт Vercel

Причина: старый аккаунт превысил Hobby-лимит `Functions Storage` (46 ГБ/10 ГБ) и `Fluid Active CPU`. `Transfer Project` недоступен без Pro-плана — сделали через **пересоздание** (`Import Git Repository` на новом аккаунте).

Что перенесли/настроили:
- **`DATABASE_URL`/`DIRECT_URL`** — та же база Supabase (проект `faravon-cafeteria`, регион South Asia), строки подключения взяты из Supabase → Connect → ORM (Prisma): транзакционный пулер (порт 6543, `?pgbouncer=true`) для `DATABASE_URL`, сессионный пулер (порт 5432) для `DIRECT_URL`. `SHADOW_DATABASE_URL` не переносили — не нужен для `prisma migrate deploy` (только для локального `migrate dev`).
- **`AUTH_SECRET`, `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`** — сгенерированы новые случайные значения (старые нигде не сохранялись).
- **`TELEGRAM_BOT_TOKEN`** — тот же, из @BotFather.
- **`BLOB_READ_WRITE_TOKEN`** — новое, отдельное Blob-хранилище на новом проекте (Storage → Create → Blob). Старые картинки (карточки/баннеры) **не перезалиты** — ссылки на них в базе продолжают вести на Blob-хранилище **старого** аккаунта и будут работать, пока то хранилище физически не удалят. Если понадобится полностью отвязаться от старого аккаунта — нужен отдельный скрипт-перезаливка (прочитать все `imageUrl` → перекачать в новый Blob → обновить записи).
- **`PLATFORM_URL`** — выставлен на `https://faravon-cafeteria.vercel.app` (без него бот не подставлял ссылку `Вход: ...` в сообщение с логином/паролем — обнаружили и починили в этой сессии).
- **Telegram webhook** — перерегистрирован на новый URL/секрет через `setWebhook` (Bot API), проверено `getWebhookInfo` — бот отвечает.
- **Cron-задачи** — было 3 (`deliver-notifications`, `sla-escalations`, `daily-digest`), на Hobby лимит 2. `sla-escalations` объединён внутрь `/api/cron/daily-digest` (см. п. 3), лишний роут и запись в `vercel.json` удалены.

Старый Vercel-проект пользователь поставил на паузу (пока не удалён).

## 2. Диагностированные и починенные баги

1. **Групповые льготы «зависали» полными** ([selection.ts](../src/lib/selection.ts), [page.tsx](../src/app/(app)/page.tsx), [flex-selection.tsx](../src/app/(app)/_components/flex-selection.tsx)) — прогресс-бар и баннер на главной считали набор кумулятивно: как только порог `minParticipants` набирался один раз, индикатор навсегда оставался зелёным/полным, и сотрудники решали, что мест больше нет, хотя выбор в новую партию по-прежнему принимался и купон выдавался сразу. Добавлена «очередь наборов» (`groupWaveOf`, коммит `e39705f`) — счётчик для интерфейса сбрасывается заново после каждого набранного порога («Групповая скидка активна · набор №2»). Реальная логика выдачи купонов не менялась.
2. **Топ слов в обращениях считал служебные сообщения бота** ([report-builder.ts](../src/lib/report-builder.ts), `f631bdf`) — «Поделился контактом», клики по готовым вопросам FAQ создают в чате автотекст с тегом `[...]` в начале тела — это не то, что человек сам напечатал. В топе лидировали «поделился», «контактом», «вопрос» вместо реальных формулировок. Такие сообщения теперь исключены из подсчёта.
3. **Журнал аудита показывал camelCase-ключи и коды ролей** ([audit/page.tsx](../src/app/(admin)/admin/audit/page.tsx), `b8ea49a`) — `+ items: 4` вместо «Позиций: 4», роли `C_AND_B`/`EMPLOYEE` вместо человеческих названий, вложенные объекты (конфиг конструктора отчётов) — как `[object Object]`. Расширен словарь `FIELD_LABELS` почти на все поля, реально встречающиеся в `audit()`-вызовах по коду; роли переводятся через `ROLE_LABELS`; `humanValue` теперь рекурсивно разбирает вложенные объекты. Добавлены недостающие подписи действий/типов сущностей.
4. **Баннеры партнёров не чистили старые файлы в Vercel Blob** ([blob-cleanup.ts](../src/lib/blob-cleanup.ts) — новый общий модуль, `ea448cc`) — при замене картинки баннера или удалении самого баннера старый файл в Blob не удалялся (у карточек льгот такая очистка уже была). Вероятная причина накопления гигабайт мусора на старом аккаунте. Вынес `cleanupBlob` в общий модуль, подключил к обоим местам.

## 3. Cron-задачи объединены (лимит Vercel Hobby)

`/api/cron/sla-escalations` удалён как отдельный роут — логика (`runSlaEscalations`) теперь вызывается внутри `/api/cron/daily-digest` перед формированием отчёта, с одной общей доставкой в Telegram в конце вместо двух отдельных. `vercel.json`:

```json
"crons": [
  { "path": "/api/cron/deliver-notifications", "schedule": "0 2 * * *" },
  { "path": "/api/cron/daily-digest", "schedule": "0 4 * * *" }
]
```

Подсказка в `/admin/sla` и README обновлены на новый путь.

## 5. Памятка для следующей сессии

- **База — Supabase, не Neon.** Комментарий в `prisma/schema.prisma` про Neon был устаревшим (историческая правка, не обновили после переезда) — если увидишь его снова, не доверяй буквально, сверяйся с реальным `DATABASE_URL`.
- **Локальная сборка проверяется через одноразовый Postgres** (`service postgresql start`, БД `ci`, `DATABASE_URL="postgresql://postgres:postgres@localhost:5432/ci?schema=public"`) — в песочнице нет доступа к прод-Supabase.
- **Исходящий доступ к `api.telegram.org` заблокирован прокси этой песочницы** — команды `setWebhook`/`getWebhookInfo` пользователь должен выполнять сам (ссылкой в браузере или curl на своей машине), агент подготовит точный URL/команду.
- Ключевые файлы этой сессии: [page.tsx (app)](../src/app/(app)/page.tsx), [flex-selection.tsx](../src/app/(app)/_components/flex-selection.tsx), [report-builder.ts](../src/lib/report-builder.ts), [audit/page.tsx](../src/app/(admin)/admin/audit/page.tsx), [blob-cleanup.ts](../src/lib/blob-cleanup.ts), [cron/daily-digest/route.ts](../src/app/api/cron/daily-digest/route.ts), [vercel.json](../vercel.json).
