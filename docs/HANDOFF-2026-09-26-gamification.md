## Финальное ревью всей ветки (диапазон 4b1b286..2fe87da) — найдено и что с этим сделано

**Critical:**
1. **C1 — фильтр задач по scope сломан.** `listAvailableTasksForEmployee` — второй `OR`
   (по `endsAt`) затирал первый (`scope`-фильтр) из-за JS object-spread. Любой сотрудник видел
   и мог взять любую активную задачу, включая задачи для другого департамента/конкретных людей.
   **Статус: ИСПРАВЛЕНО** (коммит `5223f30`), ревью (opus) подтвердило — чисто, Approved.

2. **C2 — покупка за монеты ломала обычную льготную программу.** Занимала слот
   `Period.maxSelections`, брала неверный период, подавляла авто-подбор, фармилась.
   **Решение пользователя:** отдельный настраиваемый лимит `Period.maxCoinRedemptions`
   (штук покупок за период на сотрудника), не пересекающийся с обычным лимитом; период для
   покупки за монеты — как реализовано (rolled-over в следующий период, если текущий уже
   начался — пользователь подтвердил, менять не нужно).
   **Реализовано** (коммиты `e8fca7f`, `36f6a4a`):
   - `Period.maxCoinRedemptions Int @default(1)`, `ApplicationItem.viaCoins Boolean @default(false)`
     — миграция применена на боевой БД.
   - `fulfillRedemption` (`coin-redemption.ts`) — правильный период через
     `resolveSelectionContext()`, проверка лимита, флаг `viaCoins`.
   - `countAgainstLimit` (`selection.ts`) исключает `viaCoins` — обычный лимит не трогается.
   - Авто-подбор (`ensureAutoPicks`) больше не подавляется покупками за монеты — вызывается
     ОДИН РАЗ при первом создании `Application` (внутри `fulfillRedemption`, если её ещё не
     было и окно выбора открыто), страница `(app)/page.tsx` вернула оригинальное условие
     `!application` (было временно и неправильно заменено на `!hasRealSelection` — это был
     баг ПЕРВОЙ реализации C2, найден ревью, исправлен fix-раундом).
   - UI-счётчики лимита (`(app)/page.tsx` `atSelectionLimit`, `flex-selection.tsx`
     `usedCount`/новый проп `usedForLimit`, `(app)/layout.tsx` `selectionStat.used`) —
     тоже исключают `viaCoins` (были забыты в первой версии C2-фикса, тоже найдено ревью).
   - `computeAutoProgress` (`APPLICATIONS_SUBMITTED`) исключает `viaCoins` — защита от фарма.
   - `period-lifecycle.ts` копирует `maxCoinRedemptions` в черновик следующего периода.
   - `/admin/periods` — новое поле формы «Лимит покупок за монеты» (0–20, дефолт 1).
