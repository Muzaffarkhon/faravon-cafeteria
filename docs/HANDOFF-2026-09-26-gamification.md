## Финальное ревью всей ветки (диапазон 4b1b286..2fe87da) — найдено и что с этим сделано

**Critical:**
1. **C1 — фильтр задач по scope сломан.** `listAvailableTasksForEmployee` — второй `OR`
   (по `endsAt`) затирал первый (`scope`-фильтр) из-за JS object-spread. Любой сотрудник видел
   и мог взять любую активную задачу, включая задачи для другого департамента/конкретных людей.
   **Статус: ИСПРАВЛЕНО** (коммит `5223f30`), ревью (opus) подтвердило — чисто, Approved.

2. **C2 — покупка за монеты ломала обычную льготную программу.** Занимала слот
   `Period.maxSelections`, брала неверный период, подавляла авто-подбор, фармилась.
   **Решение пользователя:** отдельный настраиваемый лимит `Period.maxCoinRedemptions`
   (штук покупок за период на сотрудника), не пересекающийся с обычным лимитом; период для
   покупки за монеты — как реализовано (rolled-over в следующий период, если текущий уже
   начался — пользователь подтвердил, менять не нужно).
   **Реализовано** (коммиты `e8fca7f`, `36f6a4a`):
   - `Period.maxCoinRedemptions Int @default(1)`, `ApplicationItem.viaCoins Boolean @default(false)`
     — миграция применена на боевой БД.
   - `fulfillRedemption` (`coin-redemption.ts`) — правильный период через
     `resolveSelectionContext()`, проверка лимита, флаг `viaCoins`.
   - `countAgainstLimit` (`selection.ts`) исключает `viaCoins` — обычный лимит не трогается.
   - Авто-подбор (`ensureAutoPicks`) больше не подавляется покупками за монеты — вызывается
     ОДИН РАЗ при первом создании `Application` (внутри `fulfillRedemption`, если её ещё не
     было и окно выбора открыто), страница `(app)/page.tsx` вернула оригинальное условие
     `!application` (было временно и неправильно заменено на `!hasRealSelection` — это был
     баг ПЕРВОЙ реализации C2, найден ревью, исправлен fix-раундом).
   - UI-счётчики лимита (`(app)/page.tsx` `atSelectionLimit`, `flex-selection.tsx`
     `usedCount`/новый проп `usedForLimit`, `(app)/layout.tsx` `selectionStat.used`) —
     тоже исключают `viaCoins` (были забыты в первой версии C2-фикса, тоже найдено ревью).
   - `computeAutoProgress` (`APPLICATIONS_SUBMITTED`) исключает `viaCoins` — защита от фарма.
   - `period-lifecycle.ts` копирует `maxCoinRedemptions` в черновик следующего периода.
   - `/admin/periods` — новое поле формы «Лимит покупок за монеты» (0–20, дефолт 1).

## Бэклог "гонки/двойные операции" — ИСПРАВЛЕНО (коммит `518217c`)

Пользователь выбрал разобрать эту группу находок сейчас (2026-09-26, та же сессия, что
закрыла скоуп-ревью fix round 1). Сделано:

  транзакции внутри `fulfillRedemption`.
- Лимит для REQUEST-режима — добавлена upfront best-effort проверка в `redeemWithCoins`
  (не тратит монеты впустую); окончательная проверка всё равно в транзакции.
- Осиротевшая APPROVED-позиция при сбое — теперь помечается `CANCELLED` (try/catch вокруг
  формирования купона внутри `fulfillRedemption`), освобождает слот лимита.
- `decideCoinRedemption` и `completeEmployeeTaskManual`/`recomputeAutoTasks` — атомарный
  claim через `updateMany(where status=...)` вместо read-then-write (это и есть I1 в
  части "claim-guard", не вся I1 — см. ниже, что осталось от I1).
- Новый `SubmitButton` (`useFormStatus`) — отключает кнопку на время pending, применён во
  всех 7 формах геймификации (это часть I3 — только UI double-click, не вся I3).
- `npx tsc --noEmit` и `npm run build` чистые. Живая браузерная проверка НЕ проводилась

**НЕ была затронута ни в фиксах, ни ещё раньше** (см. ledger для деталей):

## Ещё раньше отложенные находки (из первого финального ревью, ДО Task 11) — НЕ сделаны

Пользователь решил чинить только "гонки/двойные операции" в этой сессии, остальное
осознанно отложено как техдолг:
- I1 (частично осталось): сбои авто-покупки приза (`recomputeAutoTasks` → `rewardCompletedTask`
  → `redeemWithCoins`) всё ещё не логируются отдельно, падение всё ещё прерывает остаток
  cron-прогона (claim-guard решил только двойное выполнение, не отсутствие try/catch/аудита
  на сбой).
- I2: выбор приза заранее (`prizeCardId`) есть в бэкенде, но недостижим через UI сотрудника.
- I3 (частично осталось): кнопки в UI (`asFormAction`) всё ещё глушат `ActionResult.error`
  молча — double-click теперь защищён (`SubmitButton`), но ошибка сервера не показывается.
- I4: `redeemWithCoins`/`joinTask` не проверяют `PUBLISHED`/`isActive`/`archivedAt` карточки-
  приза — только UI-фильтр магазина.
- I5: e2e-скрипт (`scripts/gamification-e2e.ts`) деструктивен при повторном прогоне на проде
  (чистит ВСЕ монеты/позиции сотрудника ivanov, не только тестовые) — не трогать в проде без
