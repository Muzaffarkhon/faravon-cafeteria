## 0. Как продолжить на другом ноутбуке

```bash
git clone https://github.com/Muzaffarkhon/faravon-cafeteria
cd faravon-cafeteria
git checkout main         # и/или feat/admin-banners — они идентичны
npm install
```

`.env` **не едет через git** (в `.gitignore`). На новой машине нужно создать `.env` из `.env.example` и заполнить:

- `DATABASE_URL`, `SHADOW_DATABASE_URL` — та же строка Neon, что на этой машине (или локальный Postgres из `docker-compose.yml`, см. HANDOFF-09-01 §1.1). **Важно: локальный `.env` DB = продовая Neon.**
- `AUTH_SECRET` — тот же, что на этой машине (иначе разлогинит; на проде свой).
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `PLATFORM_URL` — по `.env.example`.
- `BLOB_READ_WRITE_TOKEN` — **скопировать из Vercel Dashboard → проект `faravon-cafeteria` → Storage → `faravon-cafeteria-blob`** (вкладка с ключами). Через `vercel env pull` не тянется — секретные значения CLI отдаёт как `[SENSITIVE]`.

```bash
npx prisma generate
npx prisma migrate status   # должно быть "Database schema is up to date!"
npm run dev
```

## 1. Что сделано в этой сессии (коммиты `b7e7e21` → `0c338f3`)

### 1.1. `b7e7e21` — формулировка на странице «Геймификация»
`src/app/(app)/gamification/page.tsx`. Было «баллы… за выбор льгот» → стало «баллы **за выполнение задач** и активность… и **льготы, которые можно получить за накопленные баллы**».

### 1.2. `8c67542` — авто-сжатие фото карточек + прогресс-бар
- **`src/lib/image-optimize.ts`** (новый) — клиентская оптимизация: растр ужимается по большей стороне до **1600 px** и пережимается в **WebP** (откат в JPEG) с понижением качества, пока не влезет в лимит **2 МБ**. Исходник принимается до **25 МБ** (снимок с телефона). SVG не трогается (санитизация как раньше). Экспортирует `optimizeImageFile`, `isOptimizableRaster`, `loadBitmap`, `encodeCanvasUnderLimit`.
- **`_image-field.tsx`** (поле изображения карточки) — стадии «Оптимизация…» / «Загрузка N%», прогресс-бар через `@vercel/blob@2.8.0` `onUploadProgress`.
- Замечание: HEIC (iPhone) браузер в canvas не декодирует — такое фото не сожмётся и упрётся в 2 МБ. Обычно телефоны при веб-загрузке сами отдают JPEG.

### 1.3. `ba5ea0d` — загрузка изображения баннера из системы + кадрирование
- **`src/app/(app)/_components/image-upload-field.tsx`** (новый, переиспользуемый `ImageUploadField`) — загрузка в Blob со сжатием, прогресс-баром, ручной ссылкой. При заданном `aspect` открывает **встроенный редактор кадрирования**: перетаскивание фото + ползунок «Масштаб» + кнопка «Уцентрить». Геометрия кадра выводится **чисто из состояния** (фокус-точка + зум + измеренная рамка) — иначе строгие правила `react-hooks/refs` и `set-state-in-effect` ругаются.
- **`src/lib/image-crop.ts`** (новый) — `renderCroppedFile()`: вырезает нормализованный прямоугольник → WebP/JPEG под 2 МБ.
- **`/api/cards/upload` → `/api/blob/upload`** — общий роут. Право по `clientPayload.purpose`: `card` → `cards.manage`, `banner` → `partners.manage`. Отдаёт **503** с понятным текстом, если нет `BLOB_READ_WRITE_TOKEN`.

- **`_banner-carousel.tsx`** — слайд чуть выше: `h-44 sm:h-56` → `h-52 sm:h-64`.

### 1.4. `9578be5` + `fe95196` + `8eb2959` + `b0506b4` — устойчивость загрузки

Понятные тексты: «Загрузка прервана: сервер не отвечает…» (таймаут) и «Загрузка отменена.» (кнопка). Ловит `Failed to retrieve the client token` и подменяет на подсказку про токен.

### 1.6. `8a030ab` — серверная загрузка изображений (закрывает вопрос §2)
Прямой путь **браузер → хранилище Vercel Blob** виснет и на проде (проверено пользователем: та же «Загрузка прервана: сервер не отвечает» через 45 с). Перевели загрузку на сервер.

- **`src/app/api/blob/upload/route.ts`** — добавлена ветка `multipart/form-data`: приём файла → `requireSession()` → `assertCan` по `purpose` (`card` → `cards.manage`, `banner` → `partners.manage`) → проверка типа и размера → **`put()` из серверного `@vercel/blob`** → аудит → `{ url }`. Статусы: `401` UNAUTHENTICATED, `403` FORBIDDEN, `413` >2 МБ, `415` неподдерживаемый тип, `503` нет токена. На Vercel сервер → хранилище Blob идёт внутренней сетью — надёжно; лимит тела функции ~4.5 МБ не мешает (клиент жмёт под 2 МБ). Прежняя JSON-ветка (`@vercel/blob/client` `handleUpload`) **оставлена запасным путём**.
- **`src/lib/blob-upload.ts`** — `guardedUpload()` больше **не зовёт клиентский `upload()`**, а шлёт `FormData` на `/api/blob/upload` через `XMLHttpRequest` (нужен `upload.onprogress` для полосы прогресса). Сигнатура и возврат (`done` / `cancel`) те же — оба поля изображений (`_image-field.tsx`, `image-upload-field.tsx`) **не менялись**. Сторож бездействия 45 с и кнопка «Отмена» сохранены; тексты ошибок понятные (сеть / таймаут / отмена / 5xx / 503).
- Проверено локально: `tsc`/`eslint` по изменённым файлам чисто; роут прогнан curl'ом — `400` без файла, `401` без сессии, `405` на GET, `503` без `BLOB_READ_WRITE_TOKEN`.
- Локально файловая загрузка требует `BLOB_READ_WRITE_TOKEN` в `.env` (на новом ноуте его нет — роут отдаёт `503`); до токена — «указать ссылку».

### 1.7. Public Blob-стор (`0c338f3` — пустой коммит для redeploy)
После §1.6 серверный `put()` достучался до хранилища и выдал настоящую причину:
**`Vercel Blob: Cannot use public access on a private store`**. Старый стор
(`store_fhISnXS5…`, `…private.blob.vercel-storage.com`) был создан в режиме
**Private** — режим доступа в Vercel **неизменяем после создания**.

- Старый приватный стор отключён от проекта (был пустой — файловых загрузок через
  него не было ни разу).
- Создан **новый public Blob-стор**, при создании — Access = **Public**, префикс
  переменной **пустой**, чтобы env-переменная называлась ровно
  `BLOB_READ_WRITE_TOKEN` (код читает именно это имя).
- `BLOB_READ_WRITE_TOKEN` в env проекта на Vercel (Production + Preview) обновлён
  на токен нового стора; коммит `0c338f3` — пустой, только чтобы пересобрать прод
  с новым токеном.
- **E2E на проде пройден:** `/admin/cards` → карточка → файл → загрузка без
  зависания, `imageUrl` = `https://<id>.public.blob.vercel-storage.com/…`.
- Локально: вписать новый `BLOB_READ_WRITE_TOKEN` в `.env` (из Vercel → Storage →
  новый стор → вкладка с ключами). Старый токен больше не работает.

## 2. Диагностика загрузки в Blob (история, вопрос закрыт — см. §1.6–1.7)

**Симптом был:** выбор файла в поле «Изображение» → «Загрузка…» зависает → через 45 с «Загрузка прервана: сервер не отвечает».

**Что выяснили:**
1. `BLOB_READ_WRITE_TOKEN` в `.env` **верный** (сверен с дашбордом; совпадал с `BLOB_STORE_ID = store_fhISnXS5…`).
2. `POST /api/blob/upload` → **200 OK**, клиентский токен выдаётся. БД, сессия и токен в порядке.
3. Дальше прямой запрос **браузер → `https://vercel.com/api/blob/?pathname=…`** падает; `@vercel/blob` повторяет 5+ раз с нарастающей паузой (`transferSize: 0`), затем сторож.
4. Прод проверен пользователем — **тот же результат**. Значит путь браузер → Blob плох в принципе, не только локальная сеть → перешли на серверный `put()` (§1.6).
5. Серверный `put()` достучался до хранилища и вернул **`Cannot use public access on a private store`** — оказалось, стор был **Private** (неизменяемо). Завели новый **Public** стор (§1.7). После этого E2E на проде прошёл.

**Итог:** загрузка файла изображения (карточки и баннера) на проде работает; ссылки — `*.public.blob.vercel-storage.com`.
