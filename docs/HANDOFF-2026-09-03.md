## 0. Как продолжить на другом ноутбуке

```bash
git clone https://github.com/Muzaffarkhon/faravon-cafeteria
cd faravon-cafeteria
git checkout main         # и/или feat/admin-banners — они идентичны
npm install
```

`.env` **не едет через git** (в `.gitignore`). На новой машине нужно создать `.env` из `.env.example` и заполнить:

- `DATABASE_URL`, `SHADOW_DATABASE_URL` — та же строка Neon, что на этой машине (или локальный Postgres из `docker-compose.yml`, см. HANDOFF-09-01 §1.1). **Важно: локальный `.env` DB = продовая Neon.**
- `AUTH_SECRET` — тот же, что на этой машине (иначе разлогинит; на проде свой).
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `PLATFORM_URL` — по `.env.example`.
- `BLOB_READ_WRITE_TOKEN` — **скопировать из Vercel Dashboard → проект `faravon-cafeteria` → Storage → `faravon-cafeteria-blob`** (вкладка с ключами). Через `vercel env pull` не тянется — секретные значения CLI отдаёт как `[SENSITIVE]`.

```bash
npx prisma generate
npx prisma migrate status   # должно быть "Database schema is up to date!"
npm run dev
```

## 2. Что ОСТАЛОСЬ — незакрытый вопрос: загрузка файла в Vercel Blob

**Симптом:** выбор файла в поле «Изображение» (карточки или баннера) → «Загрузка…» зависает → через 45 с «Загрузка прервана: сервер не отвечает».

**Что выяснено (диагностика в этой сессии):**
1. `BLOB_READ_WRITE_TOKEN` в `.env` **верный** (сверен с дашбордом; совпадает с `BLOB_STORE_ID = store_fhISnXS5…`).
2. `POST /api/blob/upload` → **200 OK**, клиентский токен выдаётся. Значит **БД, сессия и токен в порядке** — переподключать Neon бессмысленно.
3. Дальше идёт прямой запрос **браузер → `https://vercel.com/api/blob/?pathname=…`**, он падает; `@vercel/blob` повторяет его 5+ раз с нарастающей паузой (`transferSize: 0`), затем срабатывает сторож.
4. `@vercel/blob` повторяет **только на 5xx / 429 / сетевом сбое** — на 401/403 упал бы сразу. **Значит это не авторизация, а сетевой путь браузер → хранилище Vercel Blob.**
5. В БД **нет ни одной** `blob.vercel-storage.com` ссылки. Все текущие картинки карточек вставлены через **«указать ссылку»** (`encrypted-tbn0.gstatic.com`) или как `data:`-URL. **Файловая загрузка в Blob здесь не проходила ни разу.**
6. Чистая перепроверка (разбудить Neon → свежий `next dev` → залогиниться → загрузить) — **тот же результат**.

**Гипотеза:** путь из региона до хранилища Vercel Blob нестабилен (обрывы / 5xx / троттлинг).

### 2.1. Следующие шаги (в порядке приоритета)

1. **Проверить на проде.** Весь код задеплоен. Открыть `https://faravon-cafeteria.vercel.app/admin/cards` → новая карточка → выбрать файл.
   - **Работает** → проблема только в локальной сети. Локально пользоваться «указать ссылку», на проде — загрузкой файла. Вопрос закрыт.
   - **Не работает** → путь до Vercel Blob плох в принципе → делать п.2.
2. **Переделать на серверную загрузку** (обсуждалось, пока не начато): `<input type=file>` → `POST multipart/form-data` в наш роут → сервер сам кладёт в Blob через `put()` из `@vercel/blob` (серверный SDK). На Vercel это внутренняя сеть — надёжно. Лимит тела функции ~4.5 МБ не мешает (жмём под 2 МБ). Минус: файл проходит через функцию.
   - Затронуть: `src/app/api/blob/upload/route.ts` (добавить ветку `multipart/form-data` → `put()`), `src/lib/blob-upload.ts` (слать `FormData` вместо клиентского `upload()`), убрать `@vercel/blob/client` `upload()` из обоих полей.
3. Как временное решение уже сейчас: **«указать ссылку»** в любом поле изображения принимает готовый URL и работает всегда.
