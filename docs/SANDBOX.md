# Тестовая среда (песочница)

Отдельный деплой того же кода со **своей схемой базы**. Данные не пересекаются с
боевыми физически: тестовый деплой подключён к схеме `test` и таблиц `public`
попросту не видит. Сломать боевые данные из песочницы нельзя.

| | Боевая | Песочница |
|---|---|---|
| Адрес | `faravon-cafeteria.vercel.app` | отдельный (напр. `faravon-sandbox.vercel.app`) |
| Схема БД | `public` | `test` |
| Вход | боевые учётки | свои, заводятся внутри песочницы |
| Плашка наверху | нет | жёлтая «Тестовая среда» |

---

## 1. Схема в Supabase

Supabase → SQL Editor:

```sql
CREATE SCHEMA IF NOT EXISTS "test";
```

## 2. Таблицы в схеме `test`

Локально, с боевой строкой подключения, где `schema=public` заменён на `schema=test`:

```bash
DATABASE_URL="postgresql://...supabase.com:6543/postgres?pgbouncer=true&schema=test" \
DIRECT_URL="postgresql://...supabase.com:5432/postgres?schema=test" \
npx prisma db push
```

> **Именно `db push`, не `migrate deploy`.** Миграция `20260901221727_roles_and_banners`
> содержит `ALTER TABLE "public"."User"` — `migrate deploy` в тестовой схеме полезет
> в боевые таблицы. `db push` создаёт структуру напрямую из `schema.prisma` и
> ничего не знает про историю миграций, для песочницы это то, что нужно.
>
> Когда в боевой схеме появятся новые миграции — просто повторите `db push`
> с теми же переменными, схема подтянется.

Начальные данные (тексты, партнёры, льготы, период, учётки):

```bash
DATABASE_URL="...schema=test" DIRECT_URL="...schema=test" npm run db:seed
```

## 3. Проект в Vercel

Новый проект из того же репозитория (`Import Git Repository`), ветка `main`.

Переменные окружения:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | боевая строка пулера, но `schema=test` |
| `DIRECT_URL` | боевая прямая строка, но `schema=test` |
| `SANDBOX_LABEL` | `Тестовая среда — данные не настоящие` |
| `AUTH_SECRET` | **свой**, не боевой (иначе сессии будут ходить между средами) |
| `PLATFORM_URL` | адрес песочницы |
| `TELEGRAM_BOT_TOKEN` | **отдельный тестовый бот** или пусто (см. ниже) |
| `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET` | свои случайные |
| `BLOB_READ_WRITE_TOKEN` | своё хранилище (Storage → Create → Blob) |

`SANDBOX_LABEL` — главный признак среды: по нему включается жёлтая плашка наверху
и разблокируется кнопка очистки в разделе «Тестовая среда». На боевом деплое
переменной быть не должно.

## 4. Telegram в песочнице

Боевой токен в песочницу ставить нельзя: у бота один вебхук, и песочница
перехватит сообщения реальных сотрудников. Варианты:

- **Без бота** — оставить `TELEGRAM_BOT_TOKEN` пустым. Вход по логину и паролю
  работает, уведомления просто не уходят. Для большинства проверок достаточно.
- **Отдельный бот** — завести второго бота у @BotFather и прописать его вебхук
  на адрес песочницы.

## 5. Ссылка из боевой админки

В боевом проекте добавьте `SANDBOX_URL` с адресом песочницы — в разделе
«Тестовая среда» появится ссылка.

---

## Как пользоваться

- Раздел **Тестовая среда** в админке: внутри песочницы показывает счётчики и
  кнопку «Очистить результаты тестов» (удаляет заявки, купоны и кешбек, оставляя
  льготы, партнёров, периоды и сотрудников — сценарий можно гонять заново).
- Сотрудники, партнёры и кассиры заводятся обычным порядком в разделе
  «Пользователи» — они существуют только в песочнице.
- Проверить, что вы там, где думаете: жёлтая полоса наверху есть только в
  песочнице.
