# Чек-лист запуска на всех сотрудников

Ветка `fix/launch-blockers` закрывает найденное в аудите **на уровне кода**.
Ниже — то, что осталось и требует **вашего действия** (доступ к Vercel / Neon /
GitHub / проду) или **продуктового решения**. Порядок — по важности.

## A. Обязательно перед запуском (только вы)

1. **Прод-БД: контрольная сумма миграции `20260902050000_seed_sla_rules`.**
   Файл миграции изменён (см. `docs/MIGRATION-FIX-seed_sla_rules.md`). На проде
   один раз:
   ```bash
   # DATABASE_URL = боевая строка Neon (direct/unpooled)
   npx prisma migrate resolve --rolled-back 20260902050000_seed_sla_rules
   npx prisma migrate deploy
   ```

2. **Telegram webhook.** В хендофферах записано, что webhook был удалён для
   локального теста. Проверить и вернуть:
   ```bash
   npx tsx scripts/set-webhook.ts info      # что сейчас
   npx tsx scripts/set-webhook.ts           # зарегистрировать на https://<прод>/api/telegram
   ```
   Затем реальный `/start` в боте должен ответить. Без этого сотрудники не
   получат логины.

3. **`CRON_SECRET`** в переменных окружения Vercel (Production) + планировщик.
   См. `docs/CRON-SETUP.md`. На Hobby-тарифе Vercel Cron даёт максимум суточную
   гранулярность — для нормальной работы уведомлений и SLA нужен Vercel Pro
   **или** внешний планировщик (cron-job.org и т.п.), бьющий по
   `/api/cron/deliver-notifications`, `/api/cron/sla-escalations` каждые 10–15 мин
   и по `/api/health` каждые 5 мин.

4. **Демо-доступы на проде.** Сменить пароль `superadmin` (в хендоффе указан
   `Password1`). Удалить/выключить демо-аккаунты `ivanov`, `petrova`, `sidorov`,
   `rahmonzoda`, если они есть на боевой БД.

5. **`AUTH_SECRET`** — убедиться, что задан в Production (после правки `proxy.ts`
   без него приложение теперь fail-closed: все страницы редиректят на `/login`).

6. **Бэкапы Neon.** Free-tier не хранит бэкапы. Включить PITR (платный тариф)
   или настроить регулярный `pg_dump` в отдельное хранилище. Цель по хендоффу —
   RPO ≤ 24 ч, RTO ≤ 4 ч. Проверить восстановление на пустой БД
   (`prisma migrate deploy` теперь проигрывается с нуля — проверено в CI).

7. **CI-шаг `next build`.** Пуш из этой сессии не может менять
   `.github/workflows/` (нет scope `workflow`), поэтому изменение вынесено в
   `docs/ci-add-build-step.patch`. Применить вручную:
   ```bash
   git apply docs/ci-add-build-step.patch && git add .github/workflows/ci.yml
   git commit -m "ci: собирать приложение (next build)"
   ```

8. **Ветка `main` и защита.** После мержа `fix/launch-blockers` + патча выше
   CI станет зелёным. Включить branch protection на `main` (обязательный статус
   `verify`) — сейчас red-PR'ы мержились. Нужен GitHub Pro для приватного репо,
   либо ручной регламент «не мержить красное».

## B. Сильно желательно (можно параллельно первым пользователям)

8. **Мониторинг ошибок.** Подключить Sentry (или аналог) — сейчас только
   `console.log` в Vercel. Нужен аккаунт/DSN.

9. **Локальная разработка НЕ на проде.** В хендоффе рабочий `.env` смотрит на
   боевую Neon. Дать каждому разработчику отдельную БД (Docker из
   `docker-compose.yml` или dev-ветку Neon). `npm run db:seed` / `db:reset` /
   `flow:reset` действуют на текущий `DATABASE_URL` — с прод-строкой это стирает
   каталог льгот.

10. **Автотесты.** В `fix/launch-blockers` их нет (только `next build` в CI).
    Минимум для раската такого масштаба: юнит-тесты на `assertTransition`
    (статусная машина), `rbac.can`, выдачу/гашение купона, `safeLinkHref`,
    и smoke-e2e на основной флоу. Поставить `vitest` + прогон в CI.

11. **Мигрif рации вне сборки Vercel.** `scripts/predeploy.mjs` применяет
    `prisma migrate deploy` во время `build`. Безопаснее — отдельный
    контролируемый шаг (CI job или ручной `migrate deploy` перед промоутом).
    Оставлено как есть: фикс миграции #3 сильно снизил риск, но это остаётся
    рекомендацией.

## C. Продуктовые решения (не блокеры)

12. **Единое определение SLA.** Сейчас `reports.ts` считает рабочими днями по
    UTC-полуночи, `review-queue.ts` и `sla-escalation.ts` — по «сырым» часам.
    Плюс праздники РТ не учитываются. Выбрать одну формулу и вынести в
    `business-days.ts`; при желании — таблицу праздников.

13. **Отмена купона.** Нет пути отменить выданный по ошибке купон — только руками
    в БД. Нужна операция «отменить купон» (статус `CANCELLED`) + возврат позиции
    и уведомление сотруднику.

14. **Дедуп `update_id` вебхука** и **rate-limit на `/provider` (подбор номера
    купона)** — LOW. Первое требует таблицы обработанных апдейтов; второе
    смягчено привязкой подрядчика к партнёру и атомарным гашением. Сделать при
    появлении сигналов злоупотребления.
